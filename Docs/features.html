What runs

pnpm monorepo on Node 20–22. No auth, no multi-user: everything is hardcoded to learner-1. The API seeds one learner and three goals on every start.

API

Fastify 5 on 127.0.0.1:3100. Opens SQLite, migrates, seeds, then runs a job poller every second. apps/api/src/server.ts

Web

Vite + React SPA on 127.0.0.1:5173. Proxies /v1 and /ws to the API so the browser stays same-origin. apps/web/vite.config.ts

Provider default

Code default is mock; the local apps/api/.env currently runs PROVIDER=local with TTS_ENGINE=kokoro.

The live conversation loop

Mic audio goes up as 16 kHz PCM16 over a WebSocket; coach audio comes back paced in ~20 ms frames and resampled in the browser to the device rate.

Screens

Seven routes, each under its own error boundary. No settings, no history browser, no profile screen, no error-pattern view, and no control to accept or dismiss a correction — the transcript exists only while a session is live.

/ Session

Speak, see your words and the coach's, hear the reply, end the session.

/dashboard

CEFR ladder, estimated level with confidence, next-session plan (or an empty-plan card), skill mastery by family, last ten sessions with per-dimension scores.

/review and /review/:sessionId

The newest completed session, or a named one: dimension scores with "not assessed" for an unmeasured dimension, strengths, up to three corrections (original → suggested, with an explanation), vocabulary to keep, and the next session's topic, targets and reason. Handles loading, no-session, still-analysing and failed-analysis states.

/practice

A one-time placement from three self-ratings — labelled self-report, confidence capped at 50% — the objectives it seeds, and the recommended guided-speaking activity with its prompt, target skills and words.

/settings

Correction style, session length, feedback language and preferred accent. An unset preference stays empty — it never shows a default the learner did not choose.

/goals

List goals, add one with a type and description, mark it complete.

HTTP and WebSocket surface

Every route lives in apps/api/src/routes/. The learner ID is always learner-1; anything else returns 404.

After the session ends

Two background jobs, visible only through the review page and the dashboard. The learning engine — not the model — decides what to work on next.

JobProducesWhere
analyzeSix dimension scores, observations, skill mastery updates, error patterns, vocabulary, level estimate, and the reviewable corrected_sentences rows (skipped when the session already has them, so a retry cannot duplicate). Session becomes completed. Pronunciation stays null unless the provider declares audio-grounded evidence.apps/api/src/workers/analysis.ts
plan_nextAdjusted difficulty, primary and secondary targets, topic. The LLM picks the topic; the engine picks the targets.apps/api/src/workers/planner.ts
metricsWords per minute, pauses over 800 ms, speaking seconds.apps/api/src/metrics.ts
runnerOne-second poll, three attempts, exponential backoff, idempotent enqueue. Every attempt is recorded with an error class; a job that gives up moves its session to failed.apps/api/src/workers/jobs.ts
logsJSON-line structured logging with correlation ids — attach, re-attach, reject, job failure.apps/api/src/logger.ts

Learning engine

Pure functions, no I/O, fully unit-tested — packages/learning-engine/src/.

ModuleComputes
scoringWeighted overall score across fluency, grammar, vocabulary, pronunciation, coherence, interaction — over the assessed dimensions only; a not-assessed dimension is excluded and the rest renormalize.
masteryExponential moving average per skill (α 0.25 → 0.15) with confidence and trend.
errorsRecurrence counting, 30-day half-life decay, retirement at mastery 0.8.
difficulty±0.02 to ±0.05 steps clamped between 0.15 and 0.95.
prioritizationSix-term priority: recurrence, severity, goal relevance, communicative impact, readiness, forgetting risk.
planningTarget selection, intervention choice, CEFR banding.
activityDeterministic activity result: word coverage and speaking time scored; anything the activity cannot evidence is not_assessed and said so in words.
diagnosticSelf-report placement: band, difficulty, confidence capped at 0.5, weekly frequency capped at seven.
reviewDocumented interval policy — correct recall ×2.5, a lapse back to one day, capped at 180. Deliberately not SM-2 or FSRS and not claimed to be. Queue picks due items within a budget and alternates recognition with production.
feedbackThe review shape from a stored analysis: unassessed dimensions, top-three strengths, top-three corrections, deduped vocabulary. A suggested sentence is produced only when the wrong form actually occurs in the quoted evidence — otherwise it stays null rather than being invented.

Twenty skill codes across five families — grammar, vocabulary, fluency, pronunciation, discourse. packages/domain/src/codes.ts

Local mode now scores with the same local model that holds the conversation. Four guards sit between the model and the learner model: pronunciation is forced to null, evidence must be grounded in the learner's own words, malformed enum/skill/confidence values are repaired or dropped, and a truncated reply is salvaged.

Designed, not built

Defects worth knowing

  • gap  In openai mode every turn has zero duration, so words per minute reads zero.
  • gap  The retry and job-inspection routes exist but nothing in the web client calls them yet — recovery is an API-only path.
  • gap  The client retries a reconnect even when the server has already rejected the session (4000/4001), so a dead session burns the whole attempt budget before the UI gives up.
  • gap  The start control the client sends is ignored server-side.
  • gap  A correction's learner action is persisted but nothing sets it — there is no accept/dismiss control or route yet.
  • gap  Vocabulary review is button-driven, not a spoken or typed recall exercise — the schedule moves, the practice does not.
  • gap  Preferences are stored and reach the coach prompt, but nothing gates on them yet (session length is not enforced).
